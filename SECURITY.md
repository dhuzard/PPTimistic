# Security reporting

Do not put credentials, confidential source documents, patient information or exploitable vulnerability details in public issues or pull requests.

Check this repository's **Security** tab for an available **Report a vulnerability** action. If private vulnerability reporting is enabled, use that channel. If it is unavailable, open an issue requesting a private reporting channel without including exploit details, sensitive logs or affected private material. No private reporting email or response-time commitment is specified in this repository.

A private report should describe the affected revision, the impact, prerequisites and a minimal reproduction using synthetic data. Include relevant operating-system and Node.js versions. Keep credentials and original confidential documents out of the report.

## Version and deployment information

There is no published supported-version or security-backport schedule. Include the exact commit or version when reporting a problem. For setup, optional integrations and privacy constraints, consult [README.md](README.md) and [AGENTS.md](AGENTS.md).

Use public issues for ordinary bugs that do not expose a vulnerability or sensitive information.
